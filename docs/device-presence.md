# 在线记录与统计

在左侧打开“在线记录与统计”。平台管理员在“admin · 所有设备”查看全局，选择具体租户后只查看该租户；普通账号始终按当前角色和设备、分组授权过滤，失去授权后也无法读取该设备的历史。

每次成功认证连接保存一条记录，含设备、租户、上线时间、最后观测时间、离线时间及原因。连接关闭和心跳超时记录服务端检测时间，不能据此判断真实断电时间。无效 Token、重复 ID 拒绝不会增加上线次数。

每 10 秒最多持久化一次连接观测。服务重启后，未结束的记录以最后一次持久化观测截止，标记“服务重启，时间不确定”，不伪造精确离线时间。这部分时长是保守值，可能少于实际在线时长。首次启用前的历史不回填。

## 统计口径

时间窗口为最近 1、7、30、90 个连续自然时长日，起点不早于开始记录的时间。日统计按上海时间分桶，表格时间按浏览器本地时区显示。

- 设备总数、当前在线/离线、停用数量、当前在线占比：以当前可见、未软删除设备为集合。停用设备也可能计入离线，不把“停用”误当新断连事件。
- 上线次数：窗口内成功认证的连接次数，同一设备重连会增加次数。
- 确认断连次数：窗口内的连接关闭和心跳超时；服务重启中断单列。
- 累计在线时长：所有可见连接与窗口交集的时长之和，包含当前未结束连接。
- 平均单次观测时长：上述时长除以窗口内存在的连接片段数；它不是只对已结束连接计算的平均值。
- 最长单次观测时长：最长连接片段在窗口内的时长。
- 最近上线设备：窗口内发生过上线的设备，按最后上线时间倒序，最多 100 台。
- 每次连接记录：每页 50 条，支持加载更早记录和单设备过滤。统计量不受当前历史分页影响。

SQLite 表 `device_presence` 保留原始连接记录，当前不自动清理。软删除设备的记录仍留在数据库，但不会出现在常规统计中。

## 验证和回退

本地真实 TLS/HTTPS 协议验证（模拟设备）：

```sh
go build -o /tmp/rttys-presence ./cmd/rttys
RTTY_BINARY=/tmp/rttys-presence python3 scripts/presence-e2e.py
```

脚本创建临时数据库，覆盖无效/重复注册不计数、断连时长、心跳超时、重连、服务被终止后的恢复、跨租户拒绝、游标分页。每次运行输出证据目录，失败也保留结果。

实机重连验证会短暂停止指定设备的 rtty 服务，并在 finally 中恢复。仅在已授权的测试设备上执行：

```sh
# 先在环境中安全提供 DEVICE_PASSWORD，不把密码写进命令或证据。
python3 scripts/presence-live-e2e.py \
  --fixture /private/presence-access.json --ca /private/cert.pem \
  --device-host 172.21.0.173 --output /tmp/presence-live.json
```

2026-10-27 公网面板现为 `https://47.111.133.127:5913/`，设备 TLS 端口 5912；本次保留部署时已有端口配置。173 实机 stop/start 验证通过，页面观察到 2 次上线、1 次离线、当前在线；浏览器验证了刷新、单设备历史及时间范围切换。

部署前的二进制和一致性数据库备份：`/opt/ja-rttys/backups/presence-20261027-142221`。回退优先仅恢复二进制，保留新增历史表，避免丢失部署后的业务数据。旧版本运行期间不会记录上下线，因此再次启用本功能时存在观测缺口。
